## Design decisions locked in

### Visual identity
- **Palette:** `#F7F1DE` (cream / page bg), `#B0BA99` (sage), `#9D6638` (warm brown / accent), `#4E220F` (dark brown / header)
- **Font:** Glacial Indifference — free from fontsquirrel.com. Not on Google Fonts. Needs to be downloaded and placed at `app/static/fonts/` before the frontend build begins. Used for headings and logo text.
- **Logo:** SVG hand-coded at `app/static/logo.svg`. Transparent background, text uses `currentColor` (colour controlled via CSS). Two wave lines, π/2 phase-shifted (waves start at crest on the left edge, not at the zero crossing). Brown wave colour `#9D6638` on light backgrounds, sage `#B0BA99` on dark.

### Layout
HungerRush-style: sticky horizontal scrolling category tab bar at the top, card grid below. Mobile-first — primary use case is guests scanning a QR code on a phone.

### Category tabs
| Tab | Sources |
|---|---|
| All | All beverages + all crafted drinks |
| Beer & Wine | Grocy groups: Beer, Wine |
| Liquor | Grocy group: Liquor |
| Cocktails | All crafted drinks |
| Coffee & Tea | Grocy groups: Coffee, Tea |
| Non-Alcoholic | Coffee + Tea items + crafted drinks tagged "Non-Alcoholic", "Mocktail", or "NA" |
| THC | Grocy group: THC + crafted drinks tagged "THC" or "Cannabis" |
| Mappings *(host only)* | Ingredient mapping management UI |

All filtering is client-side. Both `/api/beverages` and `/api/crafted_drinks` are loaded on page init and filtered in the browser — no API changes needed for tabs.

### Item cards
Each card shows: **name**, **tags** (small pills), **description**.

- Cocktail description: auto-generated prose from the ingredient list — e.g. *"Bourbon, apple brandy and pear syrup"*. No new field needed.
- Beverage description: open question — Grocy `description` is currently host-only serving notes, not guest-appropriate. Needs a decision before build: either repurpose the field for guest-visible text, or leave beverage cards name-only in guest mode.

Clicking a card expands it. All users see the ingredients list when expanded. Host-only expanded sections: method steps, equipment, host notes, unmatched ingredient warnings.

### Performance
Server-side caching already handled (SQLite layer). The QR code scenario (5 simultaneous guests) is covered. Remaining improvement: add HTTP `Cache-Control` headers to API responses so browsers cache between loads. Small config change, not a redesign.

### Photos
Nice-to-have, not MVP. Would require API model changes (Notion cover images for cocktails, Grocy product pictures for beverages). Acknowledged and deferred.

## THC — design decision

**MVP approach:**
- Add "THC" as a new Grocy product group.
- Use the existing Grocy `description` field for dosage info (e.g. `"10mg THC per 1.5 oz"`).
- Frontend renders this as part of the expanded card view.
- No backend changes needed beyond the new product group.

**Post-MVP roadmap:**
- Structured dosage fields (`thc_mg_per_serving`, `serving_size_oz`) stored in SQLite and surfaced via the API.
- Grocy's quantity unit conversion system is NOT the right tool here — it doesn't model cannabinoid content per volume.

---

## Non-Alcoholic — design decision

Non-alcoholic cocktails are identified by a Notion tag. Agreed tag values: `"Non-Alcoholic"`, `"Mocktail"`, or `"NA"` (frontend checks for any of these). No Notion schema change needed — Tags is already a multi-select field.

## What's next (priority order)

### 1. Download Glacial Indifference font
Before any frontend build. Place WOFF2 file at `app/static/fonts/GlacialIndifference-Regular.woff2`. Wire up via `@font-face` in the site CSS.

### 2. Frontend build — `app/static/`
Three files: `index.html`, `app.js`, `style.css`. See design decisions above for structure. Key implementation notes:
- `x-data="app()"` on body, `app()` function defined in `app.js` loaded before Alpine
- `visibleGroups` and `visibleCocktails` computed getters drive tab filtering
- Both API endpoints fetched on init; filtering is purely client-side
- Print stylesheet hides everything except cocktail cards (for PDF menu export)

### 3. HTTP Cache-Control headers
Add to FastAPI responses so browsers cache aggressively. Particularly important for the static files. Low effort, high QR-code-scenario impact.

### 4. Mapping flow redesign (carried over from 2026-06-04 handoff)
The current mapping UI requires knowing Grocy product IDs by hand. Needs a better UX — options discussed in the previous handoff. Not blocking the frontend build.

### 5. Add "THC" product group in Grocy
Manual step in the Grocy UI. Required before any THC products will appear in the THC tab.
