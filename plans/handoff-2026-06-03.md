## What's built

### `app/db.py`
Peewee ORM models with a `DatabaseProxy` for test decoupling. All models inherit from `BaseModel` which binds to the proxy.

**`init_db(db)`** — accepts a `SqliteDatabase` instance, initialises the proxy, and creates all tables (`safe=True`).

**`JSONListField`** — custom `TextField` subclass that serialises/deserialises `list[str]` transparently. Used for `tags` and `equipment` on `CraftedDrink`.

**`CacheStatus`** — key/value table tracking last refresh timestamps per data source. Private helpers `_is_stale(cache_key, ttl_seconds)` and `_mark_refreshed(cache_key)` back four public class methods:
- `is_recipe_stale(ttl_hours=12)` / `mark_recipe_refreshed()`
- `is_grocy_stale(ttl_minutes=10)` / `mark_grocy_refreshed()`

Cache keys are private module-level constants (`_CACHE_KEY_RECIPES = "crafted_drinks"`, `_CACHE_KEY_GROCY = "grocy"`).

**`GrocyProductGroup`** — `id` (PK), `name`. `upsert_all(groups: list[dict])` — get-or-create + update loop.

**`GrocyProduct`** — `id` (PK), `name`, `product_group` (FK → `GrocyProductGroup`), `parent_product` (self-referential FK), `no_own_stock`, `description`. `upsert_all(products: list[dict])` — same pattern. **Upsert (not replace) is intentional** — `IngredientMapping` holds a FK to `GrocyProduct`; delete-and-reinsert would orphan those rows.

> Peewee naming convention: field `product_group` → column `product_group_id`, raw accessor `product_group_id`. Field `parent_product` → column `parent_product_id`, raw accessor `parent_product_id`. These match the Pydantic model field names in `models.py` exactly, so dicts from Pydantic `.model_dump()` pass through without remapping.

**`GrocyStockEntry`** — FK to `GrocyProduct` (field `product` → column `product_id`), `amount`, `location_name`, `stock_unit_name`. `replace_all(entries: list[dict])` — full delete-and-reinsert (nothing FKs to stock entries).

**`CraftedDrink`** — `notion_page_id` (PK), `name`, `glassware`, `tags` (JSONListField), `equipment` (JSONListField), `method`, `notes`, `author`. `replace_all(drinks_data: list[dict])` — atomically clears ingredients, clears drinks, then recreates both. Each dict may contain an `"ingredients"` key (list of dicts) which is popped and written as `CraftedDrinkIngredient` rows.

**`CraftedDrinkIngredient`** — FK to `CraftedDrink` (CASCADE delete), `ingredient`, `amount`, `unit`.

**`IngredientMapping`** — `id` (autoincrement PK), `notion_ingredient_name` (unique), `grocy_product` (FK → `GrocyProduct`, column `grocy_product_id`). No bulk helper — rows are managed one at a time via the host mapping UI.

## Key decisions made this session

- **Peewee over raw sqlite3** — more readable; ORM handles serialisation, FK relationships, and atomic transactions.
- **`DatabaseProxy` pattern** — models are declared once against the proxy; tests bind a fresh `:memory:` DB per test via `init_db`.
- **`CacheStatus` is source-agnostic** — named `CacheStatus` (not `NotionCacheStatus`) so Grocy caching slots in without schema changes.
- **Grocy TTL is 10 minutes** — Grocy API speed is untested; assume caching needed, revisit TTL after benchmarking.
- **Grocy upsert, not replace** — preserves `IngredientMapping` FK integrity across Grocy refreshes.
- **`cached_at` not on `CraftedDrink` rows** — per-row timestamps were misleading since refresh is always all-or-nothing. `CacheStatus` is the single source of truth for staleness.
- **`IngredientMapping` has a real FK to `GrocyProduct`** — not a bare integer. Controller should handle the case where a mapped product no longer exists in Grocy (treat ingredient as unmatched).

### Then: controller layer

`app/controllers/crafted_drinks.py` — orchestrates the cache check/refresh cycle:
1. Call `CacheStatus.is_recipe_stale()` — if stale, hit Notion, call `CraftedDrink.replace_all()`, call `CacheStatus.mark_recipe_refreshed()`
2. Read `CraftedDrink` + `CraftedDrinkIngredient` from DB
3. Look up each ingredient in `IngredientMapping` → get `grocy_product_id`
4. Check `GrocyStockEntry` for each matched product (`amount > 0`)
5. Compute `available`, populate `unmatched_ingredients`, return `CraftedDrinksResponse`

`app/controllers/beverages.py` — similar pattern for Grocy stock:
1. Check `CacheStatus.is_grocy_stale()` — if stale, hit Grocy, call `GrocyProduct.upsert_all()` + `GrocyStockEntry.replace_all()`, call `CacheStatus.mark_grocy_refreshed()`
2. Read `GrocyProduct` + `GrocyStockEntry` from DB, filter `amount > 0`
3. Group children under parents, resolve product group names
4. Return `BeveragesResponse`
